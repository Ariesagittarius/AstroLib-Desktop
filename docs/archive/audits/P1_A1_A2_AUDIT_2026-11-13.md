## 2. 审计发现

### F1（阻断，已关闭）188 章多级 slug 不可达
`cs-algorithms` 与 `science-vectors_and_tensors` 共 **188 章**的 slug 含 `/`（`zh-wp/…` 69 + `zh/…` 69 + `zh/…` 50）。P1-A1 的路由正则
`^\/?collections\/[^/]+\/[^/]+(?:\/[^/]+)?\/?$` 最多接受 3 段，多级章节直接掉出路由，落到 `resolveFilePath()` 返回 `null`，最终由 `local-server.ts` 回 **`404 text/plain`**——既不可读，也绕过了新的学术 404 视窗。
**影响**：桌面侧边栏对这些书生成的链接是 5 段 URL，用户点击即得纯文本 404；P1-A 的“1,251 章无 404”验收实际不成立。

### F2（阻断，已记录前置条件）测试依赖未跟踪生成物
`tests/unit/static-handler.test.ts` 与新增的 `reader-shell-links.test.ts` 都要求 `artifacts/abp-packs/` 存在。该目录被 `.gitignore:28` 忽略，而 `npm run build` **不打包 ABP**（只有 `npm run pack:books` 会）。因此干净 clone 直接 `npm test` 会红。
**处置**：不采用 skip（那会弱化测试），改为把 `npm run pack:books` 写进 P1-A 门禁前置与 evidence `commands`；P1-E 治理 Wave 应把该前置纳入 CI。

### F3（阻断，已关闭）学术 404 的“返回研读书库”是死按钮
404 视窗 `postMessage({type:'astrolib:switch-fragment', fragment:'library'})`，但 `FragmentReaderHost` 只有向外 `postMessage`、**没有 `message` 监听**，父窗口收不到任何指令。经 iframe 内部导航（侧栏跳转、外链）落到 404 的用户点按钮无反应，形成新的死路。

### F4（非阻断）404 视窗与 ADR §7.2 的偏差
- 图标使用 `⚠` 字符，ADR §7.2 要求 Material Symbols（`menu_book` / `error_outline`）；
- 第二个按钮为“返回上一页”（`history.back`），ADR 写的是“返回默认章节”；
- token 变量名对齐 M3，但取值在 404 页面内硬编码，未复用应用主题（含亮/暗仅跟随系统 `prefers-color-scheme`）。
均属视觉/规范层面，记入 P1-A4 或 P1-D 一并收敛，不影响契约正确性。

### F5（非阻断，平台差异）Windows 大小写不敏感导致 4 条别名返回 200
4 个仅大小写不同的 legacy 别名（如 `A1_附录A…` vs canonical `a1_附录a…`）因 NTFS 不区分大小写而**直接物理命中**，返回 200 而非 301。Linux/CI 上同一 URL 会 301。
**建议**：若要求跨平台确定性，应在命中前先校验“请求 slug 是否属于 manifest 的 canonical 集合”，否则走别名表。本轮未改，避免在 A1 边界内引入 manifest 索引变更。

### F6（非阻断）reader-shell 残留未使用导入
`reader-shell-template.ts` 仍 `import { cleanSlug }`，全文件零调用——旧 `ch.slug` 直出路径其实早已 canonical。已在 A2 删除，并新增测试断言该文件不得再引用 `cleanSlug`。
