## 2. 审计发现

### F1（阻断，已修复）reader 大纲锚点全部退化为 `#undefined`
- **事实**：`AstroBookChapterPayload.headings` 的元素类型为 `ChapterHeadingItem { depth, text, id }`，不含 `slug`；`src/pages/reader.astro` 原实现为 ``a.href = `#${h.slug}` ``。
- **量级**：全量 1,251 章中 **465 章**存在 `headings`（共 2,385 条标题），即这 465 章的大纲链接**全部失效**；构建产物中确认 `n.href = '#' + e.slug`。
- **为何门禁没拦住**：`tsc --noEmit` 不检查 `.astro` 文件中的 `<script>` 块（该项目未接 `astro check`），因此这类错误可以一路通过 `check:types` 与 `npm run build`。
- **修复（`c58456fe`）**：新增纯函数 `buildOutlineItems(headings)`——仅保留 `depth` 2/3、锚点取自 `heading.id`、跳过空锚点；`reader.astro` 改为消费该函数；补 3 条单测（字段映射、空锚点过滤、源码负向断言 `h.slug`）。重建后产物验证：`n.href = e.href`、`#undefined` 为 0。

### F2（结构性，转 P1-B）699 章的 payload 有锚点却无 headings
逐章解析统计：

| 分类 | 章数 |
|---|---:|
| headings 非空、锚点与 `html` 的 `id` 完全对齐 | 459 |
| `html` 有 `id` 锚点但 `headings` 为空（大纲无内容） | 699 |
| headings 非空但对应 `id` 不在 `html` 中（锚点断链） | 2 |
| 两者皆无 | 91 |

这属于编译器 IR 缺口（`pack-book-abp` 只对部分章节产出 `headings`，且与 `html` 锚点不同源），**不在 P1-A3 范围**，但 `/reader/` 的大纲体验依赖它在 P1-B 收敛。

### F3（门禁缺口，转 P1-E）类型门禁不覆盖 `.astro` 脚本
F1 是本轮唯一被漏掉的实质缺陷，根因是门禁只跑 `tsc`。建议 P1-E 二选一：接入 `astro check`，或规定页面脚本逻辑必须下沉到 `.ts` 纯函数（本轮修复已按后者执行）。

### F4（轻）证据与报告的 closure 口径不一致
`p1-a-evidence.json` 的 `closureCommit` 为 `0c79939f`（代码），而报告写 `closure_commit: 4188dd8b`（证据提交）。两者都不算错，但同一字段指代不同对象会造成复现歧义；建议 evidence 拆 `codeCommit` / `evidenceCommit`。

### F5（极轻）404 的“返回默认章节” href 未做 URL 编码
`/collections/${col}/${book}/${manifest.entryPoint}/` 直接拼入 `href`（已 `escapeHtml`）。浏览器可容忍中文，但规范做法是 `encodeURI()`；不影响正确性。
